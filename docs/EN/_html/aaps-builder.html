AAPS Builder

Build your own AAPS app in GitHub. No programs to install, no terminal. Takes about 10 minutes the first time, then you start each build yourself.

1Create your private build repository

This creates an empty private repository in your GitHub account. Only you can see it and the apps it builds. You do NOT need to fork AndroidAPS: the AAPS source code is downloaded from the official AndroidAPS repository at every build.

First log in to github.com in this browser (no account? create one for free). Then come back here.

Keep the suggestion. Already created your repository with another name? Type that exact name here.

Your repository:
Create my private repository

On the GitHub page that opens, the name is filled in and Private is selected. Do not change anything, do not add a README or other files.

  1. Click the green Create repository button.
  2. Come back to this page for step 2.

2Add the build workflow

The build workflow is the file that tells GitHub how to build AAPS. It comes from the AAPS documentation: view the workflow.

  2. Open the new file page

    Opens: , new file .github/workflows/build.yml

  3. Check that the file name at the top is .github/workflows/build.yml.
  4. Paste the workflow into the big text area (long press on a phone).
  5. Click Commit changes…, then Commit changes again in the window that opens.

3Your signing key

The app must be signed with your own key. Always use the same key, otherwise you have to uninstall AAPS (and lose its settings) to update.

A new key is created here in your browser. Nothing is sent anywhere.

Save a backup of your key!

Download the file and keep it somewhere safe (e.g. your own cloud storage) together with the password. You will need it if you ever build AAPS another way.

4Give the key to your repository

    KEYSTORE_SET

  4. Click "Add secret". Done, you never need to do this again.

5Build the app

  1. Open the build page

    Opens:

  2. If asked, click the green button to enable workflows.
  3. Click "Run workflow", then the green "Run workflow" button. "latest" builds the newest AAPS version.
  4. Wait about 15–30 minutes. A green check means it is done.
No "Build AAPS" / "Run workflow" button?
  1. Open your repository and check that the file .github/workflows/build.yml is there. If it is missing or has another name, do step 2 again.
  2. Open the Actions tab. If it says workflows are disabled, click the green button to enable them. Then click "Build AAPS" in the list.

6Install on your phone

⚠️ Before every update: back up your settings!
  1. In AAPS: Maintenance → Export settings. (Do this regularly anyway, e.g. after a profile change or once a month.)
  2. Copy the exported file OFF the phone, e.g. to Google Drive or Dropbox. A backup that only lives on the phone is lost together with the phone.
  3. Keep the APK files and several older exports there too. Then you can always go back.

How to export settings · AAPS FAQ: how to organize backups

  1. Open this page on your phone, in the web browser (Chrome). Not in the GitHub app: it cannot download builds. Log in to github.com if asked.
  2. Open my builds
  3. Tap the newest build with a green check ✅.
  4. Scroll down to the build summary and tap the big link "📱 Download AAPS …" (or scroll further down to "Artifacts" and tap aaps-….apk). Scroll with your finger on the text, not on the diagram of the build steps.
  5. When the download is done, tap the file and choose Install. If asked, allow installing apps from this source.
  6. aaps-wear-….apk is for a smartwatch. Skip it if you do not use one.

The APK is not shown under "Code" in your repository, only on the build page. It is kept for 14 days.

New AAPS version? Back up your settings, then build it with step 5. Your repository never builds anything by itself.

7Optional: get the app in Google Drive

Want the APK to show up in your Google Drive (kept forever)? Add one more secret.

  1. Get a GDRIVE_OAUTH2 value as explained in the AAPS documentation (it uses the official AAPS preparation page, on a computer).
    Open the AAPS guide
  2. Open the secrets page

    Opens:

  3. In "Name", enter:
    GDRIVE_OAUTH2
  4. In "Secret", paste the GDRIVE_OAUTH2 value and click "Add secret".

Next build, the APKs are also saved in Google Drive in the folder AAPS/<version>.

If you do not build for 6 months, or change your Google password, Google stops the access. The build then says so: redo this step.

Everything on this page runs in your browser. Your key and passwords are never sent anywhere except where you paste them yourself. Page and workflow are part of the AAPS documentation, based on AAPS Builder (AGPL-3.0).
