# Довідник власних циферблатів

Ця сторінка для дизайнерів нових циферблатів. Тут перелічено всі ключові слова і функції, доступні для створення або анімації нового циферблата.

- Нові функції і ключі в Custom Watchface V2 (Wear apk 3.3.0 або новіший) описано [тут](#cwf-reference-new-v2-features)

## Формат власного циферблата

Custom Watchface — відкритий формат, створений для AAPS і пов'язаний з новим циферблатом «AAPS (Custom)» на годиннику.

Файл циферблата — це звичайний zip-файл, але щоб його розпізнали як файл циферблата, zip-файл повинен містити такі файли:

- Один файл зображення з назвою CustomWatchface (це може бути растровий файл `CustomWatchface.jpg`, `CustomWatchface.png` або векторний `CustomWatchface.svg`). Цей файл — маленький значок для вибору циферблата, коли ви натискаєте кнопку «Завантажити циферблат», а також зображення в плагіні AAPS Wear.
- Один файл з назвою `CustomWatchface.json` (див. [Структура JSON](#cwf-reference-json-structure) нижче). Цей другий файл — головний. Він містить усю інформацію, потрібну для дизайну циферблата. Цей файл json має бути коректним (це, мабуть, найскладніше, коли ви редагуєте файл вручну в текстовому редакторі: одна зайва або пропущена кома вже ламає формат json). Цей файл JSON також повинен містити блок `"metadata"` з ключем `"name"`, значення якого не порожнє. Це буде назва вашого власного циферблата (див. [Налаштування metadata](#cwf-reference-metadata-settings) нижче)
- цей zip-файл має бути якомога меншим (менше приблизно 500 КБ). Якщо цей файл завеликий, його буде просто заблоковано і не передано на годинник.

Zip-файл також може містити додаткові файли ресурсів:

- Жорстко задані назви файлів зображень для стандартних елементів циферблата (наприклад, `Background`, `CoverChart`... див. [Список жорстко заданих файлів ресурсів](#cwf-reference-list-of-hardcoded-resource-files) нижче). Усі ці файли можуть бути у форматі `jpg`, `png` або `svg`. але для більшості з них потрібно використовувати `png` або `svg`, які підтримують прозорість (файли jpg менші за png, але без прозорості). Зверніть увагу: найкращу якість при найменшому розмірі зазвичай дають файли svg (векторний формат).
- Додаткові файли ресурсів з довільними назвами. Ці додаткові файли можуть бути файлами зображень або файлами шрифтів (для шрифтів підходять формати `ttf` і `otf`). Зверніть увагу: для цих додаткових файлів `filename` (без розширення) використовується як keyValue у файлі JSON, щоб указати, де або коли ці файли використовуються.
  - файли зображень часто використовують як фон текстових елементів або для динамічної анімації (наприклад, рівень заряду батареї від 0 % до 100 %)
  - файли шрифтів дають змогу використовувати на циферблаті власні шрифти

(cwf-reference-json-structure)=

## Структура JSON

Файли JSON можна редагувати в текстовому редакторі Notepad (або notepad++) (краще notepad++, який розпізнає JSON і показує його кольорами)

- він містить рядкові ключі `"string_key":` і значення ключів. Значення може бути рядком, наприклад `"key value"`, цілим числом, логічним значенням `true` або `false` чи блоком даних.
- значення відокремлюються комою `,`
- Блок даних починається з `{` і закінчується `}`
- файл json — це один цілий блок, тому він починається з `{` і закінчується `}`, а всередині файлу всі вкладені блоки пов'язані з `"key"`, який має бути унікальним у межах блоку
- Щоб файл json було легше читати, його зазвичай форматують з відступами (кожен новий ключ — з нового рядка, кожен новий блок зсунуто праворуч на 4 пробіли)

(cwf-reference-metadata-settings)=

### Налаштування metadata

Цей блок є першим блоком у файлі json і він обов'язковий. Він містить усю інформацію про цей циферблат: назву, автора, дату створення або оновлення, версію автора або версію плагіна.

Нижче наведено приклад блоку metadata:

```text
"metadata": {
    "name": "Default Watchface",
    "author": "myName",
    "created_at": "07\/10\/2023",
    "author_version": "1.0",
    "cwf_version": "1.0",
    "comment": "Default watchface, you can click on EXPORT WATCHFACE button to generate a template"
},
```

Зверніть увагу: символ `/` у даті є спеціальним символом. Щоб файл json правильно його розпізнав, перед ним треба поставити символ екранування `\`

У деяких файлах json ви можете побачити додатковий ключ `"filename"`. Цей ключ автоматично створюється або оновлюється, коли власний циферблат завантажується в AAPS (він показує користувачу назву zip-файлу в папці exports), тому ви можете видалити цей ключ з блоку metadata.

(cwf-reference-general-parameter-settings)=

### Загальні параметри

Після першого блоку metadata задаються деякі загальні параметри (див. [Список загальних параметрів](#cwf-reference-list-of-general-parameters) нижче). Вони задають кольори графіка (вуглеводи, болюс, значення ГК...), а також стандартні кольори для значень у діапазоні, гіпер або гіпо (стандартні кольори значення ГК і стрілок)

Нижче наведено приклад загальних параметрів

```text
"highColor": "#FFFF00",
"midColor": "#00FF00",
"lowColor": "#FF0000",
"lowBatColor": "#E53935",
"carbColor": "#FB8C00",
"basalBackgroundColor": "#0000FF",
"basalCenterColor": "#64B5F6",
"gridColor": "#FFFFFF",
"pointSize": 2,
"enableSecond": true,
```
(cwf-reference-imageview-settings)=

### Налаштування ImageView

Власне зображення можна налаштувати через правильну назву файлу для кожного ImageView у макеті власного циферблата. Тоді блок json потрібен лише для того, щоб задати положення, розмір, видимість елемента і, за бажанням, колір:

Нижче наведено приклад блоку зображення для second_hand (у цьому випадку в zip-файлі немає зображення, тому буде використано стандартне зображення секундної стрілки, але з власним кольором).

```text
"second_hand": {
    "width": 400,
    "height": 400,
    "topmargin": 0,
    "leftmargin": 0,
    "visibility": "visible",
    "color": "#BC906A"
}
```
Щоб second_hand мала стандартний колір ГК (lowRange, midRange або highRange), просто змініть останній рядок на keyValue `bgColor`

```json
    "color": "bgColor"
```

(cwf-reference-textview-settings)=

### Налаштування TextView

TextView have more available parameters compare to ImageView: you can tune rotation (integer value in degrees), textsize (integer value in pixel), gravity (to define if text value will be centered (default value), or aligned left or right), set the font, fontStyle and fontColor, and also background color of the TextView

```text
"basalRate": {
    "width": 91,
    "height": 32,
    "topmargin": 133,
    "leftmargin": 249,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 23,
    "gravity": "center",
    "font": "default",
    "fontStyle": "bold",
    "fontColor": "#BDBDBD"
},
```
Зверніть увагу: якщо ви не хочете використовувати якийсь елемент на своєму циферблаті, задайте ключу `"visibility"` значення `"gone"`, а також задайте розмір і положення поза видимою областю, ось так:

```text
"second": {
    "width": 0,
    "height": 0,
    "topmargin": 0,
    "leftmargin": 0,
    "rotation": 0,
    "visibility": "gone",
    "textsize": 46,
    "gravity": "center",
    "font": "default",
    "fontStyle": "bold",
    "fontColor": "#BDBDBD"
},
```
Якщо розмір і положення лежать у видимій області, під час оновлення циферблата прихований елемент може на мить «блимати».

Якщо ви хочете змінити фонове зображення текстового елемента, використайте ключ `"background":` і вкажіть як keyValue назву файлу зображення з zip-файлу. Також можна просто змінити колір фону ключем `"color:"`.

```json
"background": "fileName"
```

Також є 4 спеціальні textView (з назвами від freetext1 до freetext4), які мають окремий параметр `"textvalue":`. Його можна використати, наприклад, для підпису

(cwf-reference-chartview-settings)=

### Налаштування ChartView

Chart view — дуже особливий елемент, який може мати спільні параметри з ImageView або з TextView...

Стандартні налаштування цього елемента дуже прості:

```text
"chart": {
    "width": 400,
    "height": 170,
    "topmargin": 230,
    "leftmargin": 0,
    "visibility": "visible"
},
```
Для Chart view можна додати 2 додаткові параметри: колір фону (за замовчуванням прозорий) за допомогою ключа `"color"` або фонове зображення за допомогою ключа `"background"`.

## Як створити свій перший циферблат

### Потрібні інструменти

- Текстовий редактор: я раджу NotePad++ (або подібний) — це простий текстовий редактор, але він показує відформатований текст кольорами, тому помилки легше знайти. підійде будь-який простий текстовий редактор. Адже мета — змінювати дані json.
- Редактор зображень (растровий та/або векторний)
  - Якщо ви використовуєте растрові зображення
    - Редактор зображень повинен підтримувати прозорість (вона потрібна для всіх зображень над фоном) і формат png (якщо ви використовуєте растрові зображення)
    - Фонове зображення може бути у форматі jpg (менший за png)
    - Редактор зображень повинен давати змогу вимірювати графічні об'єкти в пікселях (це може бути простий квадрат) (top, left, width, height)
    - Редактор зображень повинен показувати кольори кодом RRGGBB у шістнадцятковому форматі
    - Редактор зображень повинен уміти змінювати розмір зображення до 400px x 400px (дуже важливо працювати саме з цією роздільністю)
  - Якщо ви використовуєте векторні зображення
    - Векторне зображення треба експортувати у формат svg

### Візьміть шаблон, щоб не починати з нуля

Свій перший циферблат найкраще почати з циферблата за замовчуванням (так у вас буде остання версія з усіма доступними елементами в правильному порядку)

- Zip-файл можна отримати, натиснувши кнопку «Експортувати шаблон» у плагіні Wear. Файл з'явиться в папці AAPS/exports
- Зверніть увагу: кнопки власного циферблата видно лише тоді, коли до AAPS підключено годинник (годинник також потрібен, щоб перевірити, протестувати й налаштувати ваш власний циферблат)

Циферблат за замовчуванням дуже простий, і zip-файл містить лише 2 файли:

- CustomWatchface.png (зображення циферблата за замовчуванням для вибору циферблата)
- CustomWatchface.json

### Упорядкуйте файли на комп'ютері

The easiest way to work is to have phone connected to the computer, and work with two specific folders:

- один провідник відкрито в окремій папці, де лежать усі файли (json, растрові зображення, векторні зображення, шрифти) і файл CustomWatchface.zip
- другий провідник (або налаштоване дерево навігації) відкрито так, щоб була доступна папка Phone/AAPS/exports

Так працювати дуже легко: щоразу, коли ви змінюєте файл json у текстовому редакторі або зображення в редакторі зображень (растровому чи векторному), вам треба лише:

1. зберегти зміни в кожному застосунку
2. перетягнути всі файли в файл CustomWatchface.zip
3. перетягнути CustomWatchface.zip у папку AAPS/exports на телефоні
4. надіслати CustomWatchface на годинник і перевірити результат

### Почніть налаштування циферблата

Спочатку задайте назву циферблата (вона потрібна, щоб легко вибрати його для тестування) і почніть змінювати ключі metadata на початку файлу json

Потім вам треба визначити, яку інформацію ви хочете показувати, тобто які елементи будуть видимі, а які приховані.

- чи будете ви показувати секунди?
- чи хочете ви зробити аналоговий годинник, цифровий годинник (або обидва...)

Тепер можна змінювати файл json: для ключа `"visibility":` кожного елемента задайте `"visible"` або `"gone"` (залежно від того, чи хочете ви залишити елемент)

You can also start to tune approximately top, left margin and width height values to start organizing the watchface (these values will be tuned later using image editor)

Примітка: усе проєктується в межах **прямокутника 400px x 400px**. Тому всі елементи розміщуються в абсолютних координатах у межах цього розміру.

Коли ви створюєте свій перший циферблат, пам'ятайте, що все впорядковано шарами від заднього до переднього, тому кожен елемент (ImageView або TextView) може закрити те, що лежить за ним...



![Шари CustomWatchface](../images/CustomWatchface_1.jpg)



У файлі json усі елементи впорядковано від заднього шару до переднього (це допоможе запам'ятати, що за чим лежить...)

Якщо ви створюєте або змінюєте свій перший власний циферблат, почніть з простого: змініть видимість деяких елементів, додайте окреме фонове зображення без зміни файлу json...

### Керування кольорами

У файлі json є кілька ключів для кольорів: `"color"`, `"fontColor"` для елементів, а також `"highColor"`, `"midColor"`, `"lowColor"`, ... (див. [Список загальних параметрів](#cwf-reference-list-of-general-parameters))

Кольори задаються текстовим полем, яке починається з `#`, а далі йдуть значення RRGGBB (Red, Green, Blue — червоний, зелений, синій) у шістнадцятковому форматі:

- `"#FFFFFF"` — білий, `"#000000"` — чорний, `"#FF0000"` — червоний...

Також можна додати 2 значення для альфа-каналу і задати рівень прозорості (AARRGGBB):

- `"#00000000"` — повністю прозорий, а `"#FF000000"` — повністю непрозорий (тому `"#FF000000"` — те саме, що `"#000000"`)

Також можна використати спеціальне значення `"bgColor"`, щоб автоматично використовувати `"highColor"`, `"midColor"`, `"lowColor"`, задані в загальних параметрах, залежно від значення ГК:

- `"fontColor": "bgColor",` автоматично задає колір шрифту елемента залежно від значення ГК
- Зверніть увагу: елементи `sgv` (значення ГК) і `direction` (стрілка тренду) автоматично використовують кольори ГК із загальних параметрів (якщо для цих 2 елементів потрібні інші кольори, використайте додаткову функцію [dynData](#cwf-reference-dyndata-feature) з кольором в один крок...)

Більше про ImageView і ключ `"color":` див. окремий розділ [Зміна кольору зображення](#cwf-reference-tune-image-color) нижче.

### Додайте жорстко задані зображення

найпростіше почати налаштування циферблата, додавши в zip-файл кілька зображень зі спеціальними назвами (див. [Список жорстко заданих файлів ресурсів](#cwf-reference-list-of-hardcoded-resource-files))

- Зображення має бути у форматі `.jpg`, `.png` або `.svg`. але будьте уважні: jpg не підтримує прозорість, тому його варто використовувати лише для фонового шару. Для всіх проміжних шарів (cover_chart, cover_plate, стрілки) використовуйте зображення `.png` або `.svg`

- Якщо у вас є векторний редактор (наприклад, Illustrator), обирайте цей формат: він дає невеликі текстові файли з розширенням `.svg` і найкращу якість.
- Уважно використовуйте точну назву файлу (з урахуванням великих і малих літер)

Тепер, якщо ви хочете окреме фонове зображення, просто додайте в zip-файл файл з назвою `Background.jpg` (більше нічого не змінюючи). Надішліть zip-файл на годинник і перевірте результат!

Якщо ви хочете змінити hour_hand, minute_hand або second_hand для аналогового годинника, просто додайте `HourHand.png` (або `HourHand.svg`), `MinuteHand.png` і `SecondHand.png`.

- ці зображення автоматично повертаються навколо центру зображення, тому вони мають показувати час 00:00:00 (а для аналогового годинника на весь екран використовуйте розмір 400 x 400 px з положенням top 0 left 0)

У [Списку жорстко заданих файлів ресурсів](#cwf-reference-list-of-hardcoded-resource-files) видно, що для кожного елемента зображення є ще дві жорстко задані назви файлів з `High` і `Low` (наприклад, можна додати в zip-файл зображення `BackgroundHigh.jpg` і `BackgroundLow.jpg`). тоді зображення автоматично змінюватиметься відповідно до рівня ГК (у діапазоні, гіпер або гіпо). Як приклад див. циферблат AIMICO.

(cwf-reference-tune-image-color)=

### Зміна кольору зображення

Ключ `"color"` можна використати, щоб змінити колір стандартного зображення:

- для елемента background він задає колір фону (за замовчуванням чорний)
- для cover_plate (простий циферблат) або стрілок він замінює стандартний колір зображення (білий) на вказаний колір (включно з `"bgColor"`)

Коли ви застосовуєте ключ `"color"` до растрового зображення (`.jpg` або `.png`), колір дає цікавий ефект на насиченість кольорів. Тож ваше растрове зображення все одно можна буде впізнати.

Для файлів зображень `.svg` ключ `"color"` не діє: кольори векторних файлів жорстко задані в самому зображенні. Якщо ви хочете змінювати кольори, додайте кілька файлів `svg` і використайте додаткову функцію [dynData](#cwf-reference-dyndata-feature)

### Додаткові шрифти для TextView

У wear apk вже є кілька стандартних шрифтів (див. ключі шрифтів у розділі [Значення ключів](#cwf-reference-key-values)). Але якщо ви хочете використати додаткові шрифти, яких немає за замовчуванням, їх можна додати в zip-файл:

- підходять 2 формати шрифтів: файли `.ttf` і `.otf`
- якщо ви додаєте в zip-файл власний шрифт, наприклад файл `myCustomFont.ttf`, то в файлі json для TextView треба вказати назву цього файлу:

```
"font": "myCustomFont",
```

Пам'ятайте, що деякі шрифти мають великі файли (а розмір zip-файлу обмежено). Якщо ви використовуєте лише кілька символів (цифри, `.`, `,`), можна безкоштовними інструментами видалити непотрібні символи (наприклад, [тут](https://products.aspose.app/font/generator/ttf-to-ttf)) і так зменшити розмір шрифту.

### Функція налаштувань

CustomWatchface може автоматично змінювати деякі налаштування годинника, щоб циферблат показувався правильно (якщо користувач дав на це дозвіл у налаштуваннях Wear).

Але цю функцію треба використовувати обережно. Налаштування спільні з усіма іншими циферблатами. Тому для цієї функції є кілька правил:

- ніколи не задавайте налаштування для прихованих елементів
- намагайтеся залишити якомога більше видимих елементів
- не бійтеся робити деякі елементи ширшими, ніж потрібно:
  - TBR може показуватися у відсотках (вузько), а також в абсолютних значеннях (набагато ширше)
  - дельта або середня дельта з детальною інформацією можуть бути широкими
  - те саме для iob2: цей елемент може показувати загальний IOB, але якщо вибрано детальний IOB, текст може бути дуже довгим

Якщо вам усе ж потрібні дуже специфічні налаштування для правильного показу (у прикладі нижче, якщо не вистачає місця для детального IOB, ви можете «примусово» задати цьому параметру годинника значення `false`), ви можете додати в блок metadata обмеження налаштувань, наприклад так

```text
"metadata": {
    "name": "Default Watchface",
    "author": "myName",
    "created_at": "07\/10\/2023",
    "author_version": "1.0",
    "cwf_version": "1.0",
    "comment": "Default watchface, you can click on EXPORT WATCHFACE button to generate a template",
    "key_show_detailed_iob": false
},
```

Якщо користувач дозволив власному циферблату змінювати параметри годинника (налаштування в плагіні Wear), то «Показати детальний IOB» буде вимкнено і заблоковано у вимкненому стані (цей параметр не можна змінити, доки дозвіл не буде вимкнено в параметрах плагіна Wear або доки не буде вибрано інший циферблат)

- Зверніть увагу: під час вибору циферблата користувач бачить кількість «обов'язкових параметрів»

У прикладі нижче циферблат Gota має один обов'язковий параметр. Якщо дозвіл не надано, число показано білим кольором. Якщо дозвіл надано, цей параметр буде задано і заблоковано на годиннику (у цьому випадку число оранжеве)

### Функція TwinView

Парні елементи (twin views) дають простий спосіб змінювати положення елемента залежно від того, які елементи видимі. Це не так гнучко, як макет повністю з LinearLayout, але підходить для багатьох типових випадків.

У прикладі нижче ви бачите циферблат AAPS (Cockpit) з усіма елементами, видимими в налаштуваннях, і той самий циферблат з вимкненими «Показати заряд пристрою» і «Показати середню дельту»

![Парні елементи](../images/CustomWatchface_3.jpg)

Видно, що коли один з парних елементів прихований, інший зсувається так, щоб бути по центру

у цьому прикладі видно, що в блок `"uploader_battery"` додано ключ `"twinView":`, який вказує на елемент `"rig_battery"`, а в блоці `"rig_battery"` ключ `"twinView":` вказує `"uploader_battery"` як парний. Додатковий ключ `"leftOffsetTwinHidden":` задає, на скільки пікселів зсунути елемент, коли парний елемент прихований.

Щоб обчислити це число: різниця між leftMargin двох парних елементів становить 50 пікселів, тому, щоб залишитися по центру, зсув дорівнює половині цього значення в один чи інший бік.

(cwf-reference-background-management)=

#### Керування фоном

По-перше, для зображення значення ГК вибору немає: воно може бути лише у фоновому шарі (інакше воно буде перед елементом chart, і графік не буде видно!). Отже, нам треба прив'язати значення ГК до фону, а потім повертати фонове зображення відповідно до значення ГК.

У блок `"background"` ми додамо 2 спеціальні ключі для цього обертання:

```text
"background": {
    "width": 400,
    "height": 400,
    "topmargin": 0,
    "leftmargin": 0,
    "dynData": "rotateSgv",
    "rotationOffset": true,
    "visibility": "visible"
},
```
Ключ `"dynData":` визначає, який блок використовувати для анімації (значення, діапазон, перетворення...). Тут цей блок має назву «rotateSgv» (коли використовуєте цю функцію, вибирайте зрозумілу назву),

`"rotationOffset": true,` задає, що анімація залежно від значення має бути обертанням. (інші доступні ключі — `"leftOffset"` і `"topOffset"`, якщо ви хочете створити повзунок)

Тепер перейдемо в кінець файлу, після останнього елемента:

```text
"second_hand": {
    "width": 120,
    "height": 120,
    "topmargin": 140,
    "leftmargin": 140,
    "visibility": "gone"
},
"dynData": {
    "rotateSgv": {
        "valueKey": "sgv",
        "minData": 30,
        "maxData": 330
    },
```
Видно, що після останнього елемента (`"second_hand"`) ми додали новий блок `"dynData": { ... }`, який міститиме всі анімації:

Блок, указаний в елементі `"background"`, має назву `"rotateSgv"`, і це перший блок у `"dynData"`!

Цей блок простий: перший ключ `"valueKey":` визначає, яке значення використовувати. у цьому випадку `"sgv"` — це «keyValue», яке означає значення ГК (зазвичай keyValue має таку саму назву, як елемент, що показує цю інформацію).

Для значення ГК стандартне min data — 39 мг/дл, а max data — 400 мг/дл (усі доступні keyValues і відповідні значення min/max data див. у [Значення ключів DynData](#cwf-reference-dyndata-key-values) нижче).

У блоці `"rotateSgv"` два додаткові ключі (`"minData":` і `"maxData":`) задають мінімальне і максимальне значення даних: 30 і 330. З цими значеннями min і max ми можемо напряму використовувати значення даних (без перетворення), щоб повертати фон у градусах. У цьому випадку всі значення ГК понад 330 мг/дл буде обмежено до 330 — верхньої межі зображення.

#### Керування графіком

Фон графіка за замовчуванням прозорий, тому, щоб приховати шкалу ГК на фоновому зображенні, нам треба додати окреме фонове зображення (воно містить загальні тіні циферблата Steampunk). Зв'язок з файлом chartBackground.jpg задається ключем `"background":`

Звісно, розмір і положення елемента треба задати з точністю до пікселя!

```text
"chart": {
    "width": 216,
    "height": 107,
    "topmargin": 280,
    "leftmargin": 80,
    "visibility": "visible",
    "background": "chartBackground"
},
```

#### Керування середньою дельтою

Щоб керувати динамічним діапазоном середньої дельти, ми використаємо чотири елементи freetext. freetext1 керує зображенням шкали, а freetext2 – freetext4 керують обертанням стрілки відповідно до шкали.

**freetext1**

Як пояснено вище, елементи freetext лежать перед графіком і перед фоном, тому ми додали прозору область, щоб було видно ці зображення (праву і нижню частину зображення)

Зверніть увагу: вирізану нижню частину цих зображень використано як фон графіка, щоб усе ідеально поєдналося.

```text
"freetext1": {
    "width": 400,
    "height": 400,
    "topmargin": 0,
    "leftmargin": 0,
    "rotation": 0,
    "visibility": "visible",
    "dynData": "avgDeltaBackground"
},
```
Для цього елемента ми додаємо посилання на інший блок `"dynData"` з назвою `avgDeltaBackground`. Цей блок керує шкалою avgDelta відповідно до значення avgDelta.

```text
"avgDeltaBackground": {
    "valueKey": "avg_delta",
    "minData": -20,
    "maxData": 20,
    "invalidImage": "steampunk_gauge_mgdl_5",
    "image1": "steampunk_gauge_mgdl_20",
    "image2": "steampunk_gauge_mgdl_20",
    "image3": "steampunk_gauge_mgdl_10",
    "image4": "steampunk_gauge_mgdl_5",
    "image5": "steampunk_gauge_mgdl_5",
    "image6": "steampunk_gauge_mgdl_10",
    "image7": "steampunk_gauge_mgdl_20",
    "image8": "steampunk_gauge_mgdl_20"
},
```
- `"valueKey":` створює зв'язок зі значенням `"avg_delta"`
- min і max Data також обмежують діапазон до максимального значення, доступного на цьому циферблаті (від -20 мг/дл до 20 мг/дл). Користувачам ммоль/л: пам'ятайте, що в AAPS усі внутрішні значення завжди в мг/дл.

Далі ми побачимо, як керувати динамічним фоновим зображенням відповідно до значення.

`"invalidImage":` — це ключ для зображення, яке показується, коли дані недійсні (або їх немає). Тут ми посилаємося на додаткове зображення в zip-файлі зі шкалою 5 мг/дл

Потім ми використаємо серію зображень від `"image1":` до `"image8":`. Кількість наданих зображень визначає кількість кроків між `minData` і `maxData`.

- `image1` задає зображення, яке показується, коли avg_delta дорівнює `minData` або близьке до нього, а зображення з найбільшим номером (тут `image8`) показується, коли avg_delta дорівнює `maxData` або близьке до нього
- від -20 мг/дл до 20 мг/дл загальний діапазон — 40 мг/дл; поділений на 8 (кількість наданих зображень), він дає 8 кроків по 5 мг/дл
- Тепер можна прив'язати фонові зображення до значення avg_delta, починаючи з найменших значень: між -20 і -15, а також між -15 і -10 для шкали використовуємо `steampunk_gauge_mgdl_20`, потім між -10 і -5 — `steampunk_gauge_mgdl_10`, і так далі до +15 і +20, де знову використовуємо фонове зображення `steampunk_gauge_mgdl_20`

(cwf-reference-dynamic-rotation-management)=

**freetext2 – freetext4**

For these views we will combine dynamic images and rotation feature explained before:

```text
"freetext2": {
    "width": 276,
    "height": 276,
    "topmargin": 64,
    "leftmargin": 64,
    "rotation": 0,
    "visibility": "visible",
    "dynData": "avgDelta5",
    "rotationOffset": true
},
"freetext3": {
    "width": 276,
    "height": 276,
    "topmargin": 64,
    "leftmargin": 64,
    "rotation": 0,
    "visibility": "visible",
    "dynData": "avgDelta10",
    "rotationOffset": true
},
"freetext4": {
    "width": 276,
    "height": 276,
    "topmargin": 64,
    "leftmargin": 64,
    "rotation": 0,
    "visibility": "visible",
    "dynData": "avgDelta20",
    "rotationOffset": true
},
```
Тут кожен елемент відповідає окремій шкалі (тому прив'язаний до окремого блоку dynData). Також видно, що ключ `"rotationOffset":` увімкнено для цих 3 елементів. Тепер погляньмо на перший блок dynData:

```text
"avgDelta5": {
    "valueKey": "avg_delta",
    "minData": -20,
    "maxData": 20,
    "rotationOffset": {
        "minValue": -120,
        "maxValue": 120
    },
    "invalidImage": "null",
    "image1": "null",
    "image2": "null",
    "image3": "null",
    "image4": "steampunk_pointer",
    "image5": "steampunk_pointer",
    "image6": "null",
    "image7": "null",
    "image8": "null"
},
```
Хоча динамічний діапазон використовується лише для даних avg_delta від -5 до +5, важливо залишити загальний діапазон від -20 до +20 мг/дл, щоб стрілка була синхронізована з фоном під час зміни шкали. Тому ми залишаємо той самий загальний діапазон, що й для `avgDeltaBackground`, і ту саму кількість кроків (8 зображень).

Зверніть увагу, що `"invalidImage"` і кілька `"imagexx"` мають значення ключа `"null"` (це може бути будь-який рядок, якого немає серед назв файлів у zip-файлі). Якщо файл з такою назвою не знайдено, фонове зображення елемента буде прозорим. Тому це налаштування гарантує, що стрілку буде видно лише на кроках 4 і 5 (середня дельта від -5 мг/дл до +5 мг/дл), а поза цим діапазоном її не буде видно.

Тепер ви бачите новий блок `"rotationOffset":`, усередині якого є два ключі: `"minValue":` і `"maxValue":`. Ці значення використовуються для перетворення між внутрішніми даними (у мг/дл) і потрібним кутом повороту.

- Циферблат Steampunk розроблено так, що стрілка повертається максимум від -30 до 30 градусів. Отже, для цієї шкали (тут від -5 мг/дл до 5 мг/дл) ми хочемо мати 30 градусів для цих значень. Оскільки `minData` і `maxData` у 4 рази більші, відповідні minValues і maxValues дорівнюють 4 * 30 градусів, тобто -120 і +120 градусів. Але при будь-якому повороті понад +-30 градусів стрілка буде прихована (зображення не видно), тому стрілку видно лише для значень від -5 до +5 мг/дл... Саме це тут і потрібно.

Інші блоки dynData задаються так само, щоб налаштувати `"avgDelta10"` і `"avgDelta20"`

#### Елемент loop

на циферблаті Steampunk зелені й червоні стрілки петлі (для статусу) вимкнено. Це теж робиться окремим блоком dynData, прив'язаним до елемента loop.

```text
    "loopArrows": {
        "invalidImage": "greyArrows",
        "image1": "greenArrows",
        "image2": "redArrows"
    }
```
Оскільки цей блок використовує лише елемент loop, а стандартні дані цього елемента — це інформація про петлю, ключ `"valueKey":` не обов'язковий.

Стандартні `minData` і `maxData` для петлі — 0 хв і 28 хв. Тому з двома зображеннями всі значення до 14 хв показуються з фоном `image1`, а всі значення понад 14 хв — з `image2`. 14 хв — це саме той поріг, на якому зелена стрілка змінюється на червону.

У цьому прикладі файлів `greyArrows`, `greenArrows` і `redArrows` немає в zip-файлі, тому ці стрілки просто прибрано (невидимі). Але ви можете використати цей блок «як є», якщо хочете змінити стрілки статусу власними фоновими зображеннями.

#### Елементи rig_battery і uploader_battery

На завершення огляду функції dynData розглянемо керування батареєю. Ідея — змінювати колір тексту залежно від рівня заряду батареї (від 0 до 100 %)

```text
"uploader_battery": {
    "width": 60,
    "height": 28,
    "topmargin": 100,
    "leftmargin": 170,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 20,
    "gravity": "center",
    "font": "default",
    "fontStyle": "bold",
    "fontColor": "#00000000",
    "dynData": "batteryIcons",
    "twinView": "rig_battery",
    "topOffsetTwinHidden": -13
},
"rig_battery": {
    "width": 60,
    "height": 28,
    "topmargin": 74,
    "leftmargin": 170,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 20,
    "gravity": "center",
    "font": "default",
    "fontStyle": "bold",
    "fontColor": "#00000000",
    "dynData": "batteryIcons",
    "twinView": "uploader_battery",
    "topOffsetTwinHidden": 13
},
```
Тут видно, що обидва елементи використовують той самий блок `dynData` з назвою `batteryIcons`. Це можливо тому, що за замовчуванням використовуються дані самого елемента (тож без ключа `"valueKey":` у блоці `batteryIcons` блок застосовується до даних `uploader_battery` або `rig_battery` залежно від елемента).

Зверніть увагу: ці два елементи також використовують функцію TwinView, описану [тут](#cwf-reference-twinview-feature).

Тепер розглянемо блок dynData:

```text
"batteryIcons": {
    "invalidFontColor": "#00000000",
    "fontColor1": "#A00000",
    "fontColor2": "#000000",
    "fontColor3": "#000000",
    "fontColor4": "#000000",
    "fontColor5": "#000000"        
},
```
Тут використано ту саму логіку, що й для динамічного фонового зображення, але зі спеціальними ключами (`"invalidFontColor"` і `"fontColor1"` – `"fontColor5"`, щоб задати 5 кроків по 20 %).

- `"fontColor1"` (темно-червоний) використовується для всіх значень нижче 20 %, а білий — для всіх значень вище цього порогу.
- Якщо ви хочете знизити поріг до «нижче 10 %», просто додайте 5 додаткових ключів від `"fontColor6"` до `"fontColor10"`. Також можна налаштувати кожен колір, якщо ви хочете плавний перехід від зеленого до жовтого, оранжевого і червоного...

(cwf-reference-dynpref-feature)=

### Функція DynPref

Перш ніж читати цей розділ, треба розуміти, як працює [dynData](#cwf-reference-dyndata-feature), бо DynPref — це розширене використання DynData: тепер ви можете налаштувати кожен блок DynData відповідно до налаштувань користувача:

Щоб показати функцію DynPref, ми використаємо два приклади:

- Циферблат Steampunk (просте використання: в одному циферблаті версії для мг/дл і ммоль/л, циферблат автоматично перемикається відповідно до одиниць, вибраних в AAPS).
- Циферблат AAPS V2 поєднує різні налаштування, щоб керувати кольором тексту і фоном відповідно до налаштувань dark і match divider.

#### Просте використання dynPref у циферблаті Steampunk

Within Steampunk, we have two sets of images according to units: `background` image that will have BG scale and will turn according to BG value. і `freeText1`, який містить динамічну шкалу залежно від значення avgDelta. Щоб один циферблат автоматично показував правильні одиниці, треба вибирати зображення відповідно до вибраних одиниць.

Для цього в блоці елемента замінимо ключ `dynData` на ключ `dynPref`:

```text
 "background": {
    "width": 400,
    "height": 400,
    "topmargin": 0,
    "leftmargin": 0,
    "dynPref": "rotateSgv",
    "rotationOffset": true,
    "visibility": "visible"
},
```
Ключі `dynPref` використовуються майже так само, як ключі `dynData`, описані в попередньому розділі

Тепер погляньмо на кінець файлу json, після блоку `dynData`:

```text
"dynData": {
    ...
},
"dynPref": {
    "rotateSgv": {
        "prefKey": "key_units",
        "true": {
            "valueKey": "sgv",
            "minData": 30,
            "maxData": 330,
            "invalidImage": "Background_mgdl",
            "image1": "Background_mgdl"
        },
        "false": {
            "valueKey": "sgv",
            "minData": 30,
            "maxData": 330,
            "invalidImage": "Background_mmol",
            "image1": "Background_mmol"
        }
    },
    ...
}
```
Видно, що ключ dynpref, заданий у блоці елемента `background` (`"dynPref": "rotateSgv"`), є в блоці json `dynPref` у кінці файлу json:

Цей блок повинен містити ключ `"prefKey"`, який визначає, яке налаштування використовувати. У цьому прикладі ключ `"key_units"` пов'язаний з одиницями, вибраними в AAPS на телефоні: значення `"true"`, якщо вибрано мг/дл, і `"false"`, якщо вибрано ммоль/л.

Далі ви знайдете два блоки json у форматі «dynData», які використовуються відповідно до вибраного налаштування

Зверніть увагу: «жорстко задану» назву файлу фонового зображення тепер замінено динамічним зображенням, яке однакове для будь-якого значення ГК (файл `Background_mgdl.png`, якщо key_units має значення «true», `Background_mmol.png`, якщо key_units має значення false). Ми також додаємо ключ `"invalidImage"`, щоб фонове зображення було завжди, навіть якщо з телефону не отримано жодних даних.

#### Поєднання різних налаштувань у dynPref на прикладі AAPS V2

Найчастіше, коли ви задаєте налаштування, вам потрібна не «динамічна поведінка», а лише результат відповідно до вибраного, але в dynPref це вважається динамічною функцією...

- у `dynData` ви задаєте один повний блок параметрів (з images, fontColor, Color, ...), а з `dynPref` можна поєднувати кожен параметр відповідно до окремого налаштування.
- Тут ми побачимо, як налаштування match divider поєднується з налаштуванням dark, щоб, коли воно ввімкнене (true), показувати білий текст на чорному фоні на темному циферблаті (dark true) або чорний текст на білому фоні на світлому циферблаті (dark false)...

Спочатку погляньмо на початок файлу json:

```text
"dynPrefColor": "prefColorDark",
"pointSize": 2,
"enableSecond": false,
"background": {
    "width": 400,
    "height": 400,
    "topmargin": 0,
    "leftmargin": 0,
    "visibility": "visible",
    "dynPref": "dark"
},
```
`"dynPrefColor": "prefColorDark"` задає блок dynPref для всіх стандартних кольорів поза елементами. Ці кольори змінюються відповідно до параметра dark у `"prefColorDark"`:

А в кінці, у блоці `dynPref`, буде окремий блок dynPref для стандартних кольорів:

```text
"prefColorDark": {
    "prefKey": "key_dark",
    "true": {
        "highColor": "#FFFF00",
        "midColor": "#00FF00",
        "lowColor": "#FF0000",
        "lowBatColor": "#E53935",
        "carbColor": "#FB8C00",
        "basalBackgroundColor": "#0000FF",
        "basalCenterColor": "#64B5F6",
        "gridColor": "#FFFFFF"
    },
    "false": {
        "highColor": "#A0A000",
        "midColor": "#00A000",
        "lowColor": "#A00000",
        "lowBatColor": "#E53935",
        "carbColor": "#D07C00",
        "basalBackgroundColor": "#0000A0",
        "basalCenterColor": "#64B5F6",
        "gridColor": "#303030"
    }
}
```
Відмінність цього блоку dynPref від інших стандартних блоків dynPref для елементів у тому, що тут немає блоку dynData для кожного значення параметра `"key_dark"`, а є лише список основних кольорів (`highColor`, `midColor`, ...)

Тепер погляньмо на елементи в «банері роздільника» (у прикладі нижче елемент `"basalRate"`, прив'язаний до dynPref `"matchDivider"`):

```text
"basalRate": {
    "width": 90,
    "height": 32,
    "topmargin": 127,
    "leftmargin": 242,
    "rotation": 0,
    ...
    "leftOffsetTwinHidden": 33,
    "dynPref": "matchDivider"
},
```
Далі в блоці dynPref видно, що параметр Match divider (ключ `key_match_divider`) містить 2 блоки «true» і «false», але ці два блоки лише задають, що елемент використовуватиме або dynBlock «dark» (тобто точно ті самі кольори фону і тексту, що й інші елементи поза банером), або dynBLock «white», який задає протилежні кольори фону і тексту...

```text
"matchDivider": {
    "prefKey": "key_match_divider",
    "true": {
        "dynPref": "dark"
    },
    "false": {
        "dynPref": "white"
    }
},
"dark": {
    "prefKey": "key_dark",
    "true": {
        "color1": "#000000",
        "fontColor1": "#FFFFFF"
    },
    "false": {
        "color1": "#FFFFFF",
        "fontColor1": "#000000"
    }
},
```
Зверніть увагу: тут ви всередині блоку «dynData», тому, щоб задати color або fontColor, використовується dynData (тут не вказано) з одним кроком (використано `"color1"` і `'fontColor1'`)

- для всіх параметрів, крім `image`, стандартне «недійсне значення» (якщо його окремо не задано ключем `"invalidColor"` або `"invalidFontColor"`) буде `"color1"` і `"fontColor1"`.



Далі третій приклад з елементами IOB (`iob1` і `iob2`), де ми використаємо менший текст для детального IOB і більший текст для загального IOB:

```text
"iob1": {
    "width": 125,
    "height": 33,
    "topmargin": 168,
    "leftmargin": 275,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 19,
    ...
    "dynPref": "prefIob1"
},
"iob2": {
    "width": 125,
    "height": 33,
    "topmargin": 196,
    "leftmargin": 275,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 24,
    ...
    "leftOffsetTwinHidden": -10,
    "dynPref": "prefIob2"
},
```
У стандартних налаштуваннях елементів ви побачите розмір тексту (19 для `iob1` і 24 для `iob2`) і два різні блоки `dynPref`, які мають змінювати textsize (залежно від параметра детального IOB) і кольори (залежно від параметра dark)

```text
"prefIob1": {
    "prefKey": "key_show_detailed_iob",
    "true": {
        "dynPref": "dark",
        "textsize1": 24
    },
    "false": {
        "dynPref": "dark"
    }
},
"prefIob2": {
    "prefKey": "key_show_detailed_iob",
    "true": {
        "dynPref": "dark",
        "textsize1": 19
    },
    "false": {
        "dynPref": "dark"
    }
},
```
Тут видно, що залежно від параметра детального IOB (ключ `"key_show_detailed_iob"`), коли він «true», textsize задано фіксованим значенням, більшим за стандартне (24 замість 19): це зроблено функцією «кроків» textsize з одним значенням, тобто одним кроком... (зверніть увагу: для всіх параметрів, крім зображень, якщо invalidTextSize не задано, для недійсних даних використовується textsize1)

Then "dark" dynPref block will be used to set color and fontColor

У цьому прикладі для елемента iob1, якщо детальний IOB увімкнено і dark увімкнено, використовується такий блок dynData:

```text
{
    "color1": "#000000",
    "fontColor1": "#FFFFFF",
    "textsize1": 24
},
```

So the text will be in white on black background and the size 24 will replace default size of 19 set into the view

Для того самого елемента iob1, якщо детальний IOB вимкнено і dark вимкнено, використовується такий блок dynData:

```text
{
    "color1": "#FFFFFF",
    "fontColor1": "#000000"
},
```

Тепер текст буде чорним на білому фоні з розміром 19

#### Поради щодо dynPref

- Можна поєднувати скільки завгодно налаштувань, але будьте уважні: кількість блоків для опису може дуже швидко зростати (експоненційно): якщо ви з'єднаєте 3 параметри і захочете описати всі ситуації, вам треба буде описати 8 блоків, навіть якщо кожен параметр має лише 2 значення...
- Будьте уважні, щоб не створити «нескінченний цикл» (наприклад, якщо блок dynpref1 доповнюється блоком dynpref2, який доповнюється блоком dynpref1...). У цьому випадку блоки dynpref вважатимуться недійсними...
- Do not forget to include the numeric index after the key (when you use for example `"textsize"`key within a view, you will have to use `"textsize1"`within the dynPref  value block, because it's a "dynData" format, so linked to value with a single step in this case)
- Для одного елемента треба задавати лише один ключ `"valueKey"`, тому, якщо остаточний блок `dynData` складається з кількох блоків `dynPref`, не додавайте кілька `"valueKey"` (і пов'язаних `"minData"`, `"maxData"`, ...)

### Нові функції в CustomWatchface V2 (AAPS V3.3.0 або новіший)

Зверніть увагу: циферблатам з цими новими функціями або елементами потрібен найновіший wear apk, зібраний з AAPS версії 3.3.0.

If you use a zip "v2" with a watch that includes CustomWatchface V1, you will have missing information or wrong content into the watchface.

CustomWatchface V2 містить такі нові функції:

- [Новий елемент Status](#cwf-reference-new-status-feature)
- [Новий елемент TempTarget](#cwf-reference-new-temp-target-feature)

- [Показ зовнішніх даних для послідовника](#cwf-reference-show-external-datas) (до 3 наборів даних на одному циферблаті: для AAPS, AAPSCLIENT і AAPSCLIENT2)

(cwf-reference-new-status-feature)=

#### Новий елемент Status

Ключ цього елемента — `"status"`, і відповідний блок автоматично додається в шаблон, експортований з wear apk «Custom Watchface V2» (зібраного з AAPS версії 3.3.0 або новішої)

Цей елемент був у попередніх циферблатах AAPS (NoChart), AAPS (BigChart) і AAPS (Large) і містить рядкове значення (сформоване в wear apk).

These previous watchfaces have been removed and replaced by 3 new custom watchfaces in AAPS 3.3.0.

- мінімальна інформація — значення IOB (видно завжди, незалежно від параметра IOB на годиннику)
- далі детальні значення IOB (BolusIOB|BasalIOB), якщо їх увімкнено в налаштуваннях
- і значення BGI (теж якщо його увімкнено в налаштуваннях)

Цей елемент `"status"` пов'язаний з ключем `"key_show_loop_status"` (у dynPref), щоб керувати видимістю.

У V1 цей елемент можна було зробити через наявні елементи `"iob1"`, `"iob2"` і `"bgi"`, але для цього потрібні складні налаштування dynPref, щоб керувати відступами між даними залежно від налаштувань, вибраних на годиннику.

(cwf-reference-new-temp-target-feature)=

#### Новий елемент TempTarget

Ключ цього елемента — `"tempTarget"`, і відповідний блок автоматично додається в шаблон, експортований з wear apk «Custom Watchface V2» (зібраного з AAPS версії 3.3.0 або новішої).

На циферблаті він показує:

- Ціль профілю (одне значення або мін–макс цілі) (стандартний колір білий)
- Ціль, змінену петлею (стандартний колір зелений)
- Тимчасову ціль, задану користувачем (стандартний колір жовтий)

Цей елемент `"tempTarget"` пов'язаний з ключем `"key_show_temp_target"` (у dynPref), щоб керувати видимістю.

Ключ DynData (пов'язаний з інформацією про колір) — `"tempTarget"` (стандартний ключ DynData для елемента TempTarget)

Значення DynData дорівнює:

- 0 (ціль профілю),
- 1 (ціль петлі) або
- 2 (тимчасова ціль користувача)

Зверніть увагу: цей елемент також доступний для зовнішніх даних (див. [нижче](#cwf-reference-show-external-datas)) з ключами `"tempTarget_Ext1"` і `"tempTarget_Ext2"` (View і DynData)

(cwf-reference-new-reservoir-level-feature)=

#### Новий елемент рівня резервуара

Ключ цього елемента — `"reservoir"`, і відповідний блок автоматично додається в шаблон, експортований з wear apk «Custom Watchface V2» (зібраного з AAPS версії 3.3.0 або новішої).

Цей елемент показує рівень резервуара (в `U`): стандартний колір білий, жовтий при рівні попередження, червоний при терміновому рівні

Цей елемент `"reservoir"` пов'язаний з ключем `"key_show_reservoir_level"` (у dynPref), щоб керувати видимістю.

Ключі DynData, пов'язані з рівнем резервуара:

-  `"reservoir"` (стандартний ключ DynData для елемента рівня резервуара) пов'язаний з рівнем інсуліну в `U`
  - Мінімальне значення — 0,0 Од
  - Максимальне значення — 500,0 Од
-  `"reservoirLevel"`
  - 0 (стандартний рівень, за замовчуванням білий колір)
  - 1 (рівень попередження, за замовчуванням жовтий колір)
  - 2 (терміновий рівень, за замовчуванням червоний колір)

Зверніть увагу: цей елемент також доступний для зовнішніх даних (див. [нижче](#cwf-reference-show-external-datas)) з ключами `"reservoir_Ext1"`, `"reservoir_Ext2"`, `"reservoirLevel_Ext1"` і `"reservoirLevel_Ext2"` (View і DynData).

(cwf-reference-new-formating-feature)=

#### Нова функція форматування для DynData або DynPref

Тепер можна задати власне форматування сирих значень, які отримує годинник і які перелічено в [таблиці значень ключів dyndata](#cwf-reference-dyndata-key-values) нижче.

Щоб показати, як працює ця функція, візьмемо як приклад циферблат AAPS (Large) і подивимося на результат залежно від «часу тому» і від того, чи видно новий елемент «status»:

![AAPS (Large)](../images/CustomWatchface_6.jpg)

- На першому знімку екрана ліворуч елемент status видно (з IOB, детальним IOB і BGI), тому для timestamp доступна лише 1/3 рядка (дуже компактно: `1'`, а для заряду батареї uploader `U: 55%`)
- На другому знімку екрана елемент `status` приховано в параметрах годинника, тому є багато місця, щоб показати повний підпис для timestamp і заряду батареї uploader (`1 minute ago` і `Uploader : 55%`)
- На третьому знімку екрана праворуч налаштування годинника точно такі самі, але timestamp змінився і став більшим за «1». тепер власний циферблат може показувати оновлений підпис з правильною множиною (`2 minutes ago`)

Нижче я не пояснюватиму, як влаштовано всі елементи в zip-файлі (положення кожного елемента залежно від різних налаштувань), а зосереджуся лише на тому, як працює функція форматування і пов'язане динамічне значення в циферблаті AAPS (Large).



**Для цієї функції потрібен «динамічний блок»** (це може бути блок `dynData` або блок `dynPref`)

- Для циферблата AAPS (Large) ми хотіли, щоб формат залежав від параметрів (короткий або довгий формат залежно від видимості елемента `status`), тому використали блок `dynPref`.

Почнімо з елементів:

```text
"uploader_battery": {
    "width": 200,
    "height": 50,
    "topmargin": 175,
    "leftmargin": 0,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 25,
    "gravity": "center",
    "font": "roboto_condensed_light",
    "fontStyle": "normal",
    "dynPref": "uploader",
    "dynValue": false,
    "fontColor": "#BDBDBD"
},

"timestamp": {
    "width": 200,
    "height": 50,
    "topmargin": 175,
    "leftmargin": 0,
    "rotation": 0,
    "visibility": "visible",
    "textsize": 25,
    "gravity": "center",
    "font": "roboto_condensed_light",
    "fontStyle": "normal",
    "dynPref": "timestamp",
    "dynValue": false,
    "fontColor": "#FFFFFF"
},
```
тут найважливіший ключ — `"dynValue"`: він вмикає динамічне керування сирим значенням. логічне значення (true або false) визначає, чи треба значення «перетворювати»

- `false`: сире значення використовується як є, без обмежень і перетворень
- `true`: сире значення буде перетворено (через ключі `minData` і `maxData` у блоці dynData і через `minValue` і `maxValue`, задані в dynData)

Для цього циферблата сирі значення використовуються без перетворення, тому для обох елементів ключ `"dynValue"` має значення `false`.



Тепер розглянемо блок `"uploader"`, заданий у `"dynPref"`:

```text
"uploader": {
    "prefKey": "key_show_loop_status",
    "true": {
        "dynPref": "uploader_true_ago",
        "invalidTextvalue": "U: --",
        "textvalue1": "U: %.0f%%"
    },
    "false": {
        "dynPref": "uploader_false_ago",
        "invalidTextvalue": "Uploader: --",
        "textvalue1": "Uploader: %.0f%%"
    }
},
```
За замовчуванням елемент `"uploader_battery"` прив'язаний до `"uploader_battery"`, тому не треба додавати окремий рядок

`"valueKey": "uploader_battery"` (мінімальне значення 0, максимальне 100, а сире значення — відсоток заряду батареї телефону)

Рядок форматування задано в ключі `"textvalue1"` (ключі `"textvalue1"`, `"textvalue2"` тощо пов'язані з ключем `"textvalue"`, який може бути в блоці `view`)

- Ключ `"textvalue"` можна використати з інформацією про форматування в блоці елемента (у цьому випадку формат буде статичним, незалежно від значення чи налаштувань)
- If you want to modify formatting information according to settings or values, then all dynData feature can be applied, and the dedicated keys are `"invalidTextValue"` key (without "formatting information" because value is not valid) and `"textvalue1"`, `"textvalue2"`... (and as many values that you want to manage steps between minData and maxData)
- додаткові ключі `"dynPref"` задають інші блоки для зміни положення і кольору залежно від видимих елементів і налаштувань dark і matchDivider

Тепер про рядок форматування. Синтаксис такий: `%[flags][width][.precision]f`

- `%` — початок форматування, `f` — кінець; його треба використовувати для перетворення значення Double.
  - Зверніть увагу: якщо ви хочете використати символ `%` у своєму рядку, пишіть `%%`, щоб показати, що це не рядок форматування, а знак відсотка.
- `[flag]` необов'язковий, зазвичай це `+`, якщо ви завжди хочете знак перед числом, або `(`, якщо хочете від'ємні значення в дужках
- `[width]` необов'язковий, задає мінімальну кількість символів у результаті
- `[.precision]` задає кількість цифр після десяткового розділювача.
  - Зверніть увагу: значення мають тип Double, тому краще завжди задавати точність (щоб не було багато символів після десяткового розділювача через точність kotlin)

Тож у прикладі вище `%.0f` покаже значення Double як ціле число



Тепер погляньмо на блок dynPref timestamp, щоб керувати множиною:

```text
"timestamp": {
    "prefKey": "key_show_loop_status",
    "true": {
        "dynPref": "timestamp_true_uploader",
        "invalidTextvalue": "U: --",
        "textvalue1": "%.0f'"
    },
    "false": {
        "dynPref": "timestamp_false_uploader",
        "minData": 0,
        "maxData": 3,
        "invalidTextvalue": "-- minute ago",
        "textvalue1": "%.0f minute ago",
        "textvalue2": "%.0f minutes ago"
    }
},
```
- тут, якщо елемент `status` видимий (тобто ключ `"key_show_loop_status"` має значення `true`), використовується один формат (`"textvalue1"`) з `'` як «одиницею»
- якщо елемент `status` прихований, використовуються 2 різні формати: один для 0 або 1 в однині, а інший для значень від 2 у множині
  - `"minData"` і `"maxData"` задають діапазон і гарантують, що перехід з однини на множину відбудеться між значеннями 1 і 2
  - Зверніть увагу: `"maxData"` (ціле число) задано як 3, а не 2, бо дані Double у системі не цілі, тому значення трохи більше або трохи менше за 1 може мати форму однини або множини, навіть якщо після округлення до цілого воно дорівнює 1.

- Для елемента `timestamp` важливо задати ключу `"dynValue"` значення `false`, інакше через форматування (однина/множина) усі значення понад 3 буде обмежено до `3 minutes ago` через перетворення з `maxData`...



**Додатковий коментар щодо функції форматування**

- пам'ятайте, що доступні лише ті динамічні значення, які перелічено [тут](#cwf-reference-dyndata-key-values)
- Усі значення `BG` у мг/дл. Якщо ви хочете функцією форматування показувати значення в ммоль/л, вам треба самостійно перетворити мг/дл на ммоль/л. У блоці `dynData` або `dynPref` блок, який містить `"minValue"` і `"maxValue"` для перетворення значення, повинен мати назву `"dynValue": { ...  }`. (див. [Ключі DynData](#cwf-reference-dyndata-keys))
- Якщо в елементі ви хочете використати статичний рядок форматування з ключем `"textvalue"` для формату і ключем `"dynValue"` для динамічного значення, то вам також треба використати блок `"dynData"` або `"dynPref"` (навіть порожній), щоб працювала функція форматування.
- `"textvalue1"`, `"textvalue2"` до textvalue*n* можна використовувати без функції форматування, щоб замінити крок значення double окремим текстовим підписом (наприклад, зі значенням ключа `"day_name"` і сімома кроками, щоб задати власні назви днів тижня, ...)

- Повну документацію див. у [Class Formatter](https://docs.oracle.com/javase/8/docs/api/java/util/Formatter.html)

#### Показ зовнішніх даних для послідовника

Тепер власний циферблат може показувати на одному циферблаті до 3 наборів даних: AAPS, AAPSCLIENT і AAPSCLIENT2

Щоб використовувати цю функцію, вам потрібно:

- мати на телефоні щонайменше 2 з 3 таких застосунків (AAPS, AAPSCLIENT, AAPSCLIENT2)
- увімкнути трансляцію даних (Broadcast data) в AAPSCLIENT та/або AAPSCLIENT2, щоб передавати дані в головний застосунок, який синхронізується з CustomWatchface (AAPS або AAPSCLIENT)
- Використовувати CustomWatchface, у якому є елементи з ключами, що містять `_Ext1` або `_Ext2` (див. [Довідник ключів і значень ключів](#cwf-reference-key-and-keyvalue-reference) нижче)

Зверніть увагу: якщо головний застосунок на телефоні — AAPSCLIENT, а другий застосунок, який транслює дані, — AAPSCLIENT2, вам треба увімкнути параметр `Switch external data in watchface` у налаштуваннях Custom Watchface, якщо ви використовуєте циферблат зі стандартними елементами і додатковими елементами Ext1 (Ext1 пов'язаний з AAPSCLIENT, а Ext2 — з AAPSCLIENT2)
